# Timetable cart summary owns Booking Title and Draft updates

Both Booking cart modes are redesigned into one shared three-region layout — a summary card, a scrollable selected-room list, and a fixed-bottom `Review & Confirm` CTA — so the required Booking Title, room count, Ministry identity, and a server-authoritative Estimated Total are all visible before either Draft exists. Booking Title moves from Booking Details into this summary card and becomes the single editable Title location for both flows; each Draft variant (Booking Draft and Recurring Series Draft) now owns Title through create, read, and update, and Booking Details renders it read-only. `Review & Confirm` no longer always creates a new Draft: the Timetable now tracks the current Draft's id (seeded from the in-app navigation state when a member returns from Booking Details) and, once set, subsequent submissions update that same Draft rather than creating a second one, so one in-progress proposal keeps one identity across edits. One-time requests one aggregate quote for every confirmed line at once — rather than summing already-fetched per-line subtotals — so the aggregate total and each line's subtotal come from a single server-authoritative response; Repeated reads its Series Estimated Total from the same debounced conflict-preview call used for CTA gating, which newlife-core-api#220 extended to also return `quotedAmount`/`currency`. This supersedes ADR 0027's cart-triggers-a-Draft-then-Details-owns-Title sequencing and ADR 0034's description of Repeated Booking Details as the Title entry point.
